# Disaster Recovery

This runbook is a proposed operator response. Automated detection/recovery is not currently implemented. Do not silently rewrite election state or treat a replacement deployment as the same election.

| Scenario | Detection | Response | Recovery | Election-integrity impact / user communication |
| --- | --- | --- | --- | --- |
| Frontend unavailable | Browser cannot load official URL/CID; compare independent hosts. | Notify users through pre-established channels; stop requesting new signatures from unknown mirrors. | Serve the exact reviewed static build via another host/gateway and publish its CID/hash. | Chain state remains; users may interact directly with verified contract, but usability/accessibility is impaired. State clearly whether voting window changes; current contract cannot extend it. |
| IPFS gateway unavailable | Gateway timeout/404 while CID known. | Try another independently operated gateway or native IPFS tooling. | Re-pin exact content and publish alternate gateway; verify CID matches. | Election state is unaffected. Metadata/frontend availability may be impaired. CID does not guarantee pinning. |
| RPC unavailable | Health/read/receipt requests fail or stale block height. | Stop treating UI state as current; do not auto-submit writes. Compare independent RPC. | Configure a verified alternate RPC and reload/re-read state. | Wallet can potentially submit through another endpoint; missed deadline risk remains. Notify voters. |
| One RPC compromised | Different chain ID/block hash/state/log results across providers. | Disable suspect endpoint; preserve request/response evidence; compare independent nodes/explorer. | Switch to independently controlled provider and verify contract code/address/current state. | Affected reads may have misled users; on-chain state is canonical according to chain consensus, not provider response. |
| Indexer unavailable | No indexer exists in current system. | Direct contract/RPC reads are current fallback. | If an indexer is later added, rebuild from chain logs and reconcile. | Indexer must never become authority. Current direct enumeration has scalability limits. |
| Wallet unavailable/disconnected | Wallet does not expose provider, account, or transaction signing. | Do not ask for private key/seed phrase; explain transaction requires a wallet. | Restore supported wallet or access via another compatible wallet controlled by the voter. | Reads may remain available; no vote can be sent. Lost wallet has no supported identity recovery. |
| Blockchain congestion | Pending transactions, gas estimates/fees rise, inclusion delayed. | Show submitted/pending status; do not automatically resubmit a vote; voter checks wallet/tx status. | Use wallet-approved fee replacement or another RPC only after checking canonical `hasVoted`. | Deadline can pass while pending; inclusion/censorship cannot be guaranteed. Communicate policy before election. |
| Chain reorganization | Previously included tx disappears or block hash changes. | Mark receipt provisional; query independent provider and current contract state. | Reconcile vote flag/tally and allow retry only if no canonical vote exists and window remains open. | Current UI lacks this handling. Never claim finality from one receipt. Notify affected users. |
| Admin key loss | Owner cannot sign a privileged call. | Stop new election setup; confirm whether existing scheduled election can proceed and whether permissionless end/finalize remains possible. | Ownership transfer is possible only if current owner can call inherited transfer; otherwise a new deployment/governance and public migration may be required. | Active vote execution may continue; pause/start recovery may be impossible. No key recovery is built in. |
| Admin key compromise | Unauthorized-looking owner calls or operator reports. | Publicly announce incident; stop directing users to compromised frontend/operations; inspect contract owner and all owner transactions. | If owner key still usable, transfer to pre-established secure governance; otherwise deploy successor and document cutover. | Eligibility/schedule/start/pause may have been manipulated. Accepted votes cannot be silently removed; consider abort under prepublished procedure. |
| Smart-contract bug | Reproducible invariant violation, unexpected state or failed calls. | Stop promotion and do not ask users to vote; preserve tx/block/bytecode/compiler evidence. | No upgrade path exists. Deploy reviewed successor only with a transparent migration/abort policy and new address. | Existing immutable state and exposed ballots remain. Do not promise restoration or rewrite history. |
| Metadata unavailable/mutated | CID missing, content hash mismatch, schema invalid, or content differs from published value. | Treat content as untrusted; compare URI/CID and any on-chain commitment. | Re-pin the exact content if CID matches; otherwise publish a correction via permitted governance before activation. | Current contract does not commit canonical metadata hash and current UI does not validate/fetch; users may have seen misleading details. |

## Recovery principles

- Contract state and canonical chain history remain authoritative; no operator database can overwrite them.
- Preserve evidence; do not delete, edit, or obscure public transactions.
- Communicate contract address, chain ID, block range, affected election and uncertainty.
- Any successor contract has a new address and must be treated as a new deployment/election unless a protocol-approved migration proves otherwise.
- No private key, seed phrase, or wallet password should ever be requested during recovery.
- Disaster exercises are required before any controlled election; this document alone does not establish operational readiness.
