# Security Matrix

| Threat | Attack | Impact | Mitigation | Implementation | Test | Residual risk |
| --- | --- | --- | --- | --- | --- | --- |
| Choice disclosure | Observer decodes candidate ID from `castVote` calldata or `VoteCast` | Voter-choice privacy lost | None in current protocol; UI warns | Plain candidate ID argument/event | No privacy regression test | Critical for secret elections; wallet-choice link is public |
| Duplicate same-wallet vote | Submit repeated/concurrent votes | Inflated tally | Per-election caller flag, atomically checked/set | Contract mapping and `castVote` | Scenario test passes | Multiple eligible wallets per person are not prevented |
| Ineligible caller | Call contract directly | Unauthorized ballot | Contract checks eligibility mapping | `eligibleVoters` check | Eligible/outsider scenario | Owner can incorrectly authorize addresses; no proof of personhood |
| Unauthorized admin call | Directly invoke setup/lifecycle methods | Election manipulation | OpenZeppelin `Ownable` | Single owner | Selected unauthorized test | Owner key is single point of failure |
| Admin-key theft | Attacker signs as owner | Eligibility/setup/pause/start control | Wallet custody only | External operational assumption | No key-compromise test | No multisig, timelock or proven recovery |
| Wrong contract/address | Configure valid but malicious address | False election UI or unintended transaction | Chain/address syntax check; wallet shows tx | Frontend config | No malicious-address test | No code hash/version allowlist or source verification |
| Wrong network | User wallet is on another chain | Failed or wrong-chain action | Network match/switch UX | wagmi chain config | No automated wallet test | Unsupported-chain and switch-race cases untested |
| Frontend compromise | Serve modified UI | User signs unintended valid vote/admin tx | Contract enforces rules, not display intent | Static UI + wallet confirmation | No E2E tamper test | UI can lie about candidate; no signed release/CSP verification |
| Malicious/stale RPC | Provider censors or lies about reads | Wrong display/unavailability | Configured-chain check and endpoint fallback for reads | Viem fallback transports; chain ID checked before contract reads | No provider fault integration test | No quorum, block-hash agreement, source check, or freshness/finality assurance |
| Reorganization | Included transaction later removed | Vote receipt/status may be inaccurate | Chain consensus only | UI waits one receipt | No reorg test | UI calls one receipt confirmed; no finality model |
| Candidate manipulation | Owner adds/reorders candidates before activation | Voters see a changed slate | Candidate writes locked outside Draft/Scheduled | Contract state gate | Freeze scenario test | No config hash, review window or multisig |
| Eligibility manipulation | Owner adds/removes wallets pre-activation | Voters excluded/extra voters included | Public tx/event and lock after Active | Owner allowlist | Freeze/admin test | No eligibility root/proof/appeal or identity governance |
| Invalid lifecycle transition | Call methods from wrong state/time | Invalid election behavior | State/time guards | Contract transitions | Selected lifecycle scenarios | Not fuzzed across all arbitrary sequences |
| Pause griefing | Owner pauses during voting | Voter opportunity reduced | Owner-only, event emitted, fixed end cannot extend | `pauseElection`/`resumeElection` | Pause/resume and deadline tests | No reason/quorum/time bound/extension policy |
| Early results API call | Request tally before finalization | Premature UI result | Getter reverts before Finalized | `getResults` guard | Test checks pre-finalized revert | Public tx/storage already leak actual votes |
| Tally modification | Admin attempts to set arbitrary count | Result integrity lost | No tally setter; counts increment in vote path | Contract storage write paths | One result scenario | No independent recount/commitment or formal invariant proof |
| Metadata tampering | URI changes or points to misleading content | Voter sees false information | URI is recorded in contract | Arbitrary string field | No CID/schema test | Mutable URL, content availability and integrity unresolved |
| RPC/contract DoS | Large candidate arrays or log range | UI reads fail or stall | Per-vote operation O(1) | Full-array getters and 10k-block scan | No capacity test | No list cap/pagination/provider range fallback |
| Transaction rejection/failure | User rejects, EVM reverts, or RPC receipt polling fails after submission | Confusion or accidental duplicate | Distinct awaiting-wallet/submitted/confirming/confirmed/timeout/failed/rejected messaging; hash retained after submission | React transaction wrapper and hash link | No wallet-driven test | No retry-receipt action or chain finality/reorg handling; user must verify before resubmitting |
| Transaction front-running/censorship | Mempool observer delays/reorders vote | Choice leaks; ballot may miss deadline | Account nonce and contract checks | Public transaction path | No adversarial ordering test | No privacy or censorship guarantee |
| Wallet phishing/compromise | User signs deceptive prompt or attacker controls key | Unauthorized vote/admin operation | App never asks for secret; confirmation names candidate | Wallet and UI | No phishing test | No domain-bound auth, verified UI, multisig, or key recovery |
| Legacy prototype reactivation | Restore old JSX entry accidentally | Plaintext credentials/localStorage fake voting | Active `index.html` currently points elsewhere | Source-level entry separation only | No build guard test | Dormant insecure modules remain in tree |
| Dependency/supply-chain attack | Compromised dependency or changed `latest` resolution | Malicious build or runtime | Lockfile and npm audit | npm dependency tooling | Audit evidence only | `latest` ranges, no SBOM/signing/CI or license checks |
| Accessibility exclusion | Keyboard/screen reader cannot use ballot | Voter cannot participate reliably | Semantic controls and some ARIA labels | Current React UI | No automated/manual WCAG report | Modal focus management and WCAG conformance unverified |
| Coercion/vote buying | Attacker forces or purchases vote proof | Choice autonomy compromised | No effective mitigation | Public transaction proves candidate | Not tested | Explicitly outside current guarantee |
| Chain outage/congestion | Blocks delayed or chain unavailable | Missed vote/deadline | Alternative RPC is possible manually | No built-in failover | No chaos test | No availability/SLA/extension mechanism |
